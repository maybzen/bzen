# 비젠커뮤니케이션 회계관리 시스템

**BZen Communication** 내부용 회계 관리 웹앱입니다.
정적인 목업이 아니라 **실제로 데이터가 저장되고, 여러 사람이 함께 쓰는** 배포용 시스템입니다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 임원진(관리자) · 직원 |
| 주요 기능 | 매출 · 매입 · 운영비 · 지출결의 · 프로젝트별 손익 · 보고서 |
| 로그인 | 개인별 계정 + 역할 구분(관리자/직원) |
| 데이터 | Supabase (PostgreSQL + Storage, 서울 리전) |
| 배포 | GitHub Pages (push 하면 자동 배포) |

---

## 1. 바로 실행하기

```bash
npm install     # 최초 1회
npm run dev     # http://localhost:5173
```

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (핫 리로드) |
| `npm run build` | 배포용 정적 파일을 `dist/` 에 생성 |
| `npm run preview` | 빌드 결과를 로컬에서 미리보기 |

### 하위 경로로 빌드할 때

GitHub Pages 는 `https://아이디.github.io/저장소이름/` 형태로 배포되므로 base 경로를 지정합니다.

```powershell
# Windows PowerShell
$env:VITE_BASE="/bzen-accounting/"; npm run build

# macOS / Linux
VITE_BASE=/bzen-accounting/ npm run build
```

배포 워크플로(`.github/workflows/deploy-pages.yml`)는 저장소 이름을 자동으로 읽어 `VITE_BASE` 를 넣어 줍니다.
따라서 **push 만 하면** 별도 설정 없이 배포됩니다.

## 2. 최초 사용 순서

1. 배포 주소에 접속합니다.
2. 관리자 계정이 하나도 없으면 **「최초 관리자 계정 만들기」** 화면이 자동으로 나타납니다.
   - 이름 · 이메일 · 비밀번호(6자 이상)를 입력하면 그 계정이 **관리자**가 됩니다.
3. 로그인 후 `계정관리` 에서 직원 계정을 추가합니다.
   - 직원은 **본인이 등록한 지출결의만** 조회·수정할 수 있습니다.
   - 관리자는 전체 장부 조회·수정, 프로젝트 등록, 계정관리가 가능합니다.
4. `프로젝트` 를 먼저 등록해 두면 매출·비용을 프로젝트에 연결해 **손익이 자동 집계**됩니다.

> 마지막 남은 관리자 계정은 권한을 내리거나 삭제할 수 없습니다. 관리자 계정을 최소 1개 유지하세요.

## 3. 회계 처리 규칙

| 구분 | 설명 |
| --- | --- |
| 금액 입력 | **공급가액 + 부가세** 를 따로 입력하고 합계는 자동 계산됩니다. |
| 영업이익 | `매출(공급가액) − 매입(공급가액) − 운영비(공급가액)` — **부가세 제외 기준**입니다. |
| 부가세 납부 예상 | `매출세액 − 매입세액(매입+운영비)` |
| 프로젝트 손익 | 장부 입력 시 프로젝트를 지정하면 자동으로 집계됩니다. 지정하지 않으면 `프로젝트 미지정` 으로 남습니다. |
| 지출결의 | 승인 절차 없이 **기록 전용**입니다. 직원이 증빙과 함께 등록합니다. |

> 부가세는 통과 항목이므로 손익 계산에서 제외했습니다. 현금 흐름은 `합계` 열을 참고하세요.

## 5. 자료를 계속 추가하는 방법

### 5-1. 화면에서 직접 입력 (일상 업무)

각 장부 화면의 **등록** 버튼으로 건별로 입력합니다.
영수증·세금계산서 등 증빙 파일을 함께 첨부할 수 있습니다(파일당 최대 20MB, 비공개 보관).

### 5-2. CSV 일괄등록 (엑셀에 정리해 둔 자료)

`매출 / 매입 / 운영비` 화면 → **CSV 일괄등록** → **양식 다운로드** 후 작성해 올리면 한 번에 등록됩니다.

| 구분 | 열 이름 |
| --- | --- |
| **필수** | `일자`(YYYY-MM-DD), `공급가액` |
| 선택 | `거래처`, `항목`, `적요`, `부가세`, `결제수단`, `비고`, `프로젝트` |

`프로젝트` 는 등록된 프로젝트 이름과 **정확히 일치**해야 연결됩니다.

### 5-3. 내려받기

- 각 장부 화면 → **CSV 내보내기** (현재 필터 조건 그대로)
- `보고서` 화면 → **요약 CSV**(손익·월별·프로젝트별·항목별) / **상세 CSV**(전체 거래) / **인쇄·PDF**

## 6. 프로젝트 구조

```
├─ index.html
├─ vite.config.js               # VITE_BASE 하위 경로 지원
├─ tailwind.config.js           # 색상·타이포 토큰
├─ .env.production              # 배포 빌드용 공개 설정 (커밋됨)
├─ .github/workflows/           # GitHub Pages 자동 배포
├─ public/favicon.svg
└─ src/
   ├─ main.jsx / App.jsx        # 라우팅 · 접근 권한 가드
   ├─ auth/AuthContext.jsx      # 세션 · 프로필 · 권한
   ├─ lib/
   │  ├─ supabase.js            # 클라이언트
   │  ├─ api.js                 # 데이터 계층 (장부·프로젝트·첨부·설정)
   │  ├─ constants.js           # 유형·항목·상태 정의
   │  ├─ format.js              # 금액·날짜·기간 계산
   │  ├─ summary.js             # 손익 집계 로직
   │  └─ csv.js                 # CSV 내보내기/불러오기
   ├─ components/               # Layout · 표 · 차트 · 입력 모달 · 토스트
   └─ pages/                    # Dashboard · LedgerPage · Projects …
```

### 데이터 모델 (Supabase)

| 테이블 | 역할 |
| --- | --- |
| `profiles` | 사용자 · 역할(admin/staff) · 부서 · 사용여부 |
| `projects` | 프로젝트 마스터 (계약금액·기간·담당자) |
| `entries` | **통합 장부** — `entry_type`(sale/purchase/opex) + `source`(manual/expense_report) |
| `attachments` | 증빙 파일 메타데이터 (실제 파일은 Storage `receipts` 버킷) |
| `settings` | 회사명 · 사업자등록번호 |

**`entries` 한 테이블로 매출·매입·운영비·지출결의를 모두 관리**합니다.
유형만 다르고 구조가 같아, 보고서 집계가 단순하고 일관됩니다.

## 7. 보안

| 항목 | 처리 |
| --- | --- |
| 데이터 접근 | 데이터베이스 **RLS(행 수준 보안)** 로 통제. 관리자만 전체 열람, 직원은 본인 지출결의만. |
| 자가 가입 | 가입해도 `비활성 + 직원` 으로만 생성되어 아무 데이터도 볼 수 없습니다. |
| 계정 생성 | 관리자 권한을 확인하는 Edge Function(`admin-users`)을 통해서만 가능. |
| 증빙 파일 | 비공개 버킷에 저장, 열람 시에만 1시간짜리 임시 주소 발급. |
| 검색 노출 | `noindex, nofollow` 로 검색엔진 수집 차단. |

> `.env.production` 의 Supabase `anon` 키는 **브라우저에 공개되도록 설계된 키**입니다.
> 실제 보호는 위 RLS 정책이 담당하므로 저장소에 포함되어도 데이터는 안전합니다.

## 8. 운영 · 유지보수

| 상황 | 방법 |
| --- | --- |
| 코드 수정 후 배포 | `main` 브랜치에 push → GitHub Actions 자동 배포 |
